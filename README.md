Переиспользуемый дочерний шаблон на базе стандартного шаблона **Cassiopeia** для **Joomla 4, 5 и 6**. 

Проект создан прежде всего для личного использования и разработки собственных сайтов/магазинов на Joomla, выложен в открытый доступ на GitHub для удобного версионирования, фиксации правок и дальнейшего развития.

### Ключевые возможности и надстройки:
* **Адаптивная модульная шапка:** вынесена в `header/`, поддержка сменных макетов (`header_layout`), верхняя плашка (топбар) + бургер + мобильный оффканвас.
* **Встроенный оффканвас:** автоматическое клонирование главного меню (`html/mod_menu/offcanvas.php`) с раскрывающимися подпунктами.
* **Свободные секции:** позиции `section-1` … `section-4` со стилем модуля `section` (`html/layouts/chromes/section.php`) и суффиксами фона/отступов (`soft`, `gray`, `primary`, `dark`, `sm`, `lg`, `nopad`).
* **Локальная типографика и стили:** подключение шрифта Manrope (`woff2` 400, 500, 600, 700) без внешних запросов к Google Fonts, переменные цветов в `:root`, кнопки с ripple-эффектом.
* **Набор векторных mask-иконок:** телефон, почта, адрес, часы, поиск, корзина, соцсети (Telegram, VK, MAX) в `media/images/ico/`.
* **Универсальная страница ошибки:** брендированная страница `error.php` (404, 403, 500) с кнопками возврата и поддержкой темной/светлой темы через CSS-переменные.
* **Инсталлятор `script.php`:** автоматическое копирование логотипа/favicon в `images/dharma_starter/` и создание модуля главного меню при первой установке.

## Быстрый старт и сборка

Готовый установочный архив можно скачать со страницы [Releases](https://github.com/shivayanamahom/dharma-starter/releases).

Для сборки архива из исходников выполните:
```bash
./build.sh
```
Собранный пакет появится в `dist/dharma_starter-<версия>.zip` и выведет SHA256-хэш для обновления ленты `updates.xml`.

## Обновления шаблона через Joomla

Шаблон поддерживает нативную систему обновлений Joomla («Система» → «Обновления» → «Расширения»).

В манифест `templateDetails.xml` подключен сервер обновлений:
```xml
<updateservers>
    <server type="extension" priority="1" name="Dharma Starter Updates">https://raw.githubusercontent.com/shivayanamahom/dharma-starter/main/updates.xml</server>
</updateservers>
```
При публикации нового релиза на GitHub и обновлении `updates.xml` на ветке `main`, административная панель Joomla автоматически предложит установить обновление в один клик.

## Установка

### Вариант 1: Прямая установка по URL (рекомендуется)
1. В админке Joomla: **Система** → **Установка** → **Расширения** → вкладка **«Установить по URL-адресу»**.
2. Вставьте прямую ссылку на архив актуального релиза:
   ```text
   https://github.com/shivayanamahom/dharma-starter/releases/download/v1.2.22/dharma_starter-1.2.22.zip
   ```
3. Нажмите **«Проверить и установить»**.

### Вариант 2: Установка из архива
1. Скачайте zip-архив со страницы [Releases](https://github.com/shivayanamahom/dharma-starter/releases).
2. В админке Joomla: **Система** → **Установка** → **Расширения** → вкладка **«Загрузить файл пакета»**.
3. Перетащите скачанный zip в область загрузки.

---

### Настройка после установки
1. Назначить `Dharma Starter` шаблоном по умолчанию для сайта (**Система** → **Шаблоны сайта**).
3. Меню создаётся при установке: инсталлятор добавляет модуль «Главное меню»
   (`mod_menu`) в позицию `menu` на все страницы, на первый тип меню сайта
   (на чистой Joomla это `mainmenu`). Это одно и то же меню: оно рисуется и в
   верхней плашке (топбар), и клонируется в оффканвас (бургер «Меню») с
   макетом `html/mod_menu/offcanvas.php` и раскрывающимися подпунктами.
   Если в позиции `menu` уже есть модуль (переустановка, ручная настройка),
   инсталлятор ничего не трогает и дублей не создаёт. Хотите другое меню —
   поменяйте тип меню в этом модуле или опубликуйте свой модуль `mod_menu` в
   позицию `menu`.
4. Заполнить параметры шаблона (см. ниже) — логотип, контакты, соцсети.
5. Инсталлятор (`script.php`) сам, без дополнительных действий:
   - копирует логотип/favicon из шаблона в `images/dharma_starter/logo.png`
     и `images/dharma_starter/favicon.svg`;
   - создаёт главное меню в позицию `menu` (см. п. 3);
   - устанавливает подготовленные макеты меню, секций и других элементов Joomla;
   - ставит универсальную страницу ошибки `error.php` (см. ниже).

   > Имя класса в `script.php` должно быть `dharma_starterInstallerScript`
   > (элемент шаблона + `InstallerScript`, без префикса `tpl_`), иначе Joomla
   > не найдёт класс и инсталлятор не выполнится. Папка `html` должна быть
   > перечислена в `<files>` манифеста `templateDetails.xml`, иначе оверрайды
   > не попадут на сайт.

## Позиции модулей

`menu`, `search`, `cart`, `header-actions`, `banner`,
`breadcrumbs`, `main-top`, `main-bottom`, `sidebar-left`, `sidebar-right`,
`footer`, `debug`.

Телефон, e-mail, адрес и иконки соцсетей (Telegram/MAX/VK) — **не модули**,
а параметры шаблона (вкладка «Брендинг» → вкл/выкл + ссылка на каждую
соцсеть). Показываются в шапке и повторно в оффканвасе на мобильных.

## Кнопка обратного звонка

В шапке стоит кнопка `.callback` (`.dharma-header__callback`) со ссылкой
`href="#"`. Формы в шаблоне нет — её выводит отдельный модуль-конструктор
форм, который привязывается к этой кнопке по классу `.callback`.

## Секции

В шаблоне есть четыре свободные позиции `section-1`…`section-4`. Они выводятся
между основным содержимым и подвалом, **без обёртки** (`style="none"`), как и
остальные позиции: никаких `card` и лишних контейнеров, разметку секции задаёт
сам модуль (например, «Произвольный HTML» со своим `<section>`). Пустая позиция
не создаёт разметки.

Для своей вёрстки в шаблоне есть готовые классы:

| Класс | Что делает |
|---|---|
| `dharma-section` | вертикальные отступы секции |
| `dharma-section--sm`, `--lg`, `--nopad` | меньшие, большие и нулевые отступы |
| `dharma-section--soft`, `--gray`, `--primary`, `--dark` | фон (на тёмном и фирменном текст белый) |
| `dharma-section__title` | крупный заголовок секции |

Пример содержимого модуля: `<section class="dharma-section dharma-section--soft"><div class="container">…</div></section>`.

**Готовая обёртка (по желанию).** Если не хочется писать `<section>` руками,
у модуля в «Расширенные» → «Стиль модуля» выберите «section»
(`html/layouts/chromes/section.php`). Тогда модуль оборачивается в `<section>`
сам, а вид задаётся словами в поле «Суффикс класса модуля» через пробел: фон
`soft | gray | primary | dark`, отступы `sm | lg | nopad`, `full` — содержимое
на всю ширину (иначе в контейнере). Пример: `dark lg`. Другие слова добавляются
как обычные CSS-классы, заголовок модуля выводится как `<h2 class="dharma-section__title">`.

**Нужна ещё секция:** добавьте её имя (например, `section-5`) в массив в
`index.php` (блок «Секции» перед подвалом) и строку
`<position>section-5</position>` в `templateDetails.xml`. После обновления
манифеста позиция появится в списке «Позиция» в редакторе модуля; пока её там
нет, имя можно просто вписать в поле вручную.

## Макеты шапки

Шапка вынесена из `index.php` в папку `header/`:

```text
header/
  default.php            макет «default»: верхняя плашка + главная шапка
  partials/offcanvas.php оффканвас-меню (общая часть, подключается макетами)
```

В параметрах шаблона («Разметка» → «Макет шапки») список строится из файлов
папки `header/`. Чтобы сделать новый макет, скопируйте `header/default.php`
в `header/<имя>.php`, измените разметку, и макет сам появится в списке. Если
выбранного файла нет (или в имени посторонние символы), используется `default`.

Макет получает из `index.php` готовые переменные: `$this`, `$params`, `$e()`
(экранирование), `$logoUrl`, `$logoAlt`, `$contactPhone`, `$phoneHref`,
`$contactEmail`, `$contactAddress`, `$socialLinks`. `use`-импорты в подключаемых
файлах нужно объявлять самим.

На телефоне и планшете (до 992 px) главная шапка всегда прижата к верху экрана
(`position: sticky`, без отступа у страницы); на десктопе она в потоке, а
залипание включает параметр «Залипающая шапка». Якорные ссылки учитывают высоту
шапки (`scroll-padding-top`).

Разметка шапки: верхняя плашка с меню — обычный блок `.dharma-header`, а
главная шапка — семантический `<header class="dharma-header__main">` прямо в
`<body>`. Так логотип и навигация лежат внутри ориентира `banner`, а «залипание»
шапки (`position: sticky`) продолжает работать. Не оборачивайте её в ещё один
контейнер: sticky ограничивается родителем.

## Font Awesome

Параметр «Загружать Font Awesome» («Разметка»). Шаблон рисует свои иконки
сам (mask-иконки из `media/images/ico`), но Font Awesome подключает родительский
Cassiopeia и он нужен иконкам стандартных модулей и компонентов (вход,
пагинация, поиск и др.). Если на сайте они не используются, параметр можно
выключить: страница теряет около 100 КБ CSS и 155 КБ шрифта. Отключение сделано
перерегистрацией ассета Cassiopeia без зависимости (обычное `disableStyle`
не помогает: зависимость пресета возвращается). Перед отключением просмотрите
сайт: часть иконок ядра может пропасть. Параметр действует и на страницу ошибки.

## Доступность

- Первая ссылка на странице «Перейти к содержимому» (видна при фокусе с
  клавиатуры) ведёт на `#main-content`.
- У кнопки-бургера есть `aria-label` (на узких экранах текст скрыт).
- У верхнего меню и меню оффканваса свои подписи `aria-label`.

## Логотип и favicon

В параметрах шаблона («Брендинг») логотип и favicon выбираются обычным
полем медиа-менеджера Joomla с превью, а не вводом пути. Старые значения
(просто путь вида `images/dharma_starter/logo.png`) продолжают работать.

По умолчанию Joomla не считает `svg` и `ico` изображениями, поэтому SVG-favicon
в медиа-менеджере не выбрать, пока в «Система → Параметры → Медиа → Допустимые
расширения изображений» не добавлены `svg` и `ico`. PNG выбирается сразу;
SVG, подставленный по умолчанию, работает без настройки.

## Страница ошибки

`error.php` — универсальная страница для 404, 403, 500 и т. д.: логотип из
параметров шаблона, крупный код ошибки, кнопка «На главную» (при ошибках,
отличных от 404, ещё «Обновить страницу»). Тексты лежат в языковых файлах
шаблона (`TPL_DHARMA_STARTER_ERROR_*`, русский и английский), цвета берутся из
CSS-переменных `--dharma-*`, поэтому страница подхватывает бренд сайта
без правок. Техническая информация (сообщение и backtrace) показывается
только в режиме отладки Joomla и не для 404.

## Иконки

`media/images/ico/*.svg` — набор для `.ico-*` классов (phone, mail, pin,
clock, search, cart, telegram, max, vk, user, comment, chevron, arr).
Однотонные иконки красятся через `mask` + `currentColor`, брендовые
(telegram/max/vk) — через `background-image` в своих фирменных цветах.

## Кнопки

`.knopka` / `.knopka2` — основная/контурная кнопка с ripple-эффектом на
hover (класс `.ripple-hover`, JS создаёт `<span class="ripple">` в точке
курсора). `.ar-arrow` — стрелка внутри кнопки.

## Цвета

Все цвета — CSS-переменные в `:root` (`--dharma-primary`,
`--dharma-secondary`, `--dharma-ink`, `--dharma-muted`, ...), плюс `-rgb`
пары для `rgba()` и проброс в нативные `--link-color`/`--link-hover-color`
Cassiopeia, чтобы стандартные компоненты (`.btn-link`, `.nav`, `.pagination`)
тоже подхватывали бренд. `--dharma-radius`/`--dharma-shadow`/`--dharma-border`
смотрят в нативные переменные Cassiopeia — поменяется в конструкторе
шаблона, подхватится и тут.

## Брейкпоинты

Стандартные бутстраповские, mobile-first (`min-width`), все блоки собраны
ЕДИНЫМ блоком в конце `user.css` (после всех базовых правил — иначе при
равной специфичности победит более позднее по файлу правило, а не
media-condition, и адаптив перестанет работать). Новые адаптивные правила
дописывать внутрь уже существующего блока нужного размера, не создавать
новый `@media` по ходу файла.

## Уменьшение движения

`@media (prefers-reduced-motion: reduce)` в конце файла уважает только
крупное движение (автоскролл). Декоративные микро-анимации (dropdown,
ripple, кольцо у кнопки звонка и т.п.) намеренно не гасятся — на сайте нет
ничего того масштаба, от которого предостерегает WCAG, а точечное глушение
каждой анимации по одной оказалось источником постоянных "анимация не
работает" багов.

## Важно при доработке XML параметров

У этой версии Joomla (com_templates) каждый `<fieldset>` в
`templateDetails.xml` должен становиться своей вкладкой в настройках стиля —
но на практике вкладкой становится только первый добавленный fieldset,
остальные проваливаются плоским списком под «Подробности». Поэтому у нас
всего 2 fieldset'а (`branding`, `layout`) — новые поля добавлять **внутрь
существующих**, а не создавать третий fieldset.

Также: description любого поля не должен содержать сырых `<`/`>` — Joomla
не экранирует текст, и браузер словит его как открывающий тег, из-за чего
всё, что рендерится после, проваливается внутрь этого битого тега (в т.ч.
родная вкладка «Привязка к меню»).
