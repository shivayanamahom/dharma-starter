# Правила и архитектура Dharma Starter для ИИ-агентов (AGENTS.md)

Этот документ предназначен для ИИ-ассистентов (Claude, Antigravity, Codex, Cursor и др.) и разработчиков, работающих над кодовой базой дочернего шаблона **Dharma Starter** (`tpl_dharma_starter`).

---

## 1. Контекст и архитектура проекта

1. **Тип расширения:** Дочерний шаблон (Child Template) для стандартного шаблона **Cassiopeia** (`parent = cassiopeia`) в **Joomla 4, 5 и 6**.
2. **Назначение:** Персональный переиспользуемый шаблон с модульной адаптивной шапкой, оффканвас-меню, локальными шрифтами, векторными SVG-иконками, готовыми макетами секций и оверрайдами интернет-магазина (RadicalMart).
3. **Репозиторий:** `shivayanamahom/dharma-starter` (ветка `main`).

---

## 2. Железные правила кодовой базы

### 2.1. Манифест `templateDetails.xml`
- **Список файлов `<files>`:** В манифесте ОБЯЗАТЕЛЬНО должны быть перечислены все папки и файлы корня шаблона (`header`, `html`, `images`, `language`, `index.php`, `error.php`, `script.php`, `joomla.asset.json`). Если создаётся новая папка в корне, её необходимо добавить в `<files>`, иначе инсталлятор Joomla проигнорирует её при установке/обновлении.
- **Вкладки параметров (`<fieldset>`):** В `com_templates` Joomla вкладкой становится только первый добавленный филдсет; последующие проваливаются в плоский список. Поэтому в шаблоне зафиксировано ровно 2 филдсета: `branding` и `layout`. **Новые параметры добавлять внутрь существующих филдсетов, не создавать третий!**
- **Опасные символы в `description`:** Ни в коем случае не использовать неэкранированные угловые скобки `<` или `>` внутри атрибутов `description=""` в XML. Joomla парсит их в открытый HTML-тег, что ломает рендеринг формы параметров и вкладку «Привязка к меню».
- **Секция `<updateservers>`:** Всегда должна указывать на `https://raw.githubusercontent.com/shivayanamahom/dharma-starter/main/updates.xml`.

### 2.2. Скрипт установки `script.php`
- **Имя класса:** Должно быть строго `dharma_starterInstallerScript` (элемент шаблона + `InstallerScript` без префикса `tpl_`). Префикс `tpl_` ломает вызов скрипта установщиком Joomla.
- Скрипт копирует дефолтные изображения бренда в `images/dharma_starter/` и создаёт модуль меню в позиции `menu` (если он ещё не создан). Не ломать идемпотентность этих проверок.

### 2.3. Стили и адаптив (`media/css/user.css`)
- **CSS-переменные:** Все базовые цвета задаются в `:root` с префиксом `--dharma-*` и дублируются парой `-rgb` для поддержки `rgba()`. Они пробрасываются в нативные `--link-color`/`--link-hover-color` Cassiopeia.
- **Единый блок медиа-запросов (КРИТИЧНО):** Все правила `@media (min-width: ...)` собраны **в самом конце файла `user.css`** единым блоком (mobile-first). **Запрещено** раскидывать медиа-запросы по телу файла — из-за специфичности CSS в Joomla это ломает адаптивную вёрстку на мобильных. Любые новые адаптивные стили дописывать только внутрь существующего блока нужного брейкпоинта.
- **Анимации и WCAG:** В блоке `prefers-reduced-motion` отключаются только крупные автоскроллы. Микро-анимации (dropdown, ripple, кольцо звонка) глушить нельзя.

### 2.4. Модульная шапка (`header/`)
- Шапка вынесена из `index.php` в файлы `header/*.php` (по умолчанию `default.php`).
- Общая часть мобильного меню лежит в `header/partials/offcanvas.php`.
- Главный контейнер шапки — семантический `<header class="dharma-header__main">` на верхнем уровне `<body>`. **Не оборачивать его в дополнительные контейнеры** с `overflow`, иначе перестанет работать залипание (`position: sticky`).

### 2.5. Оверрайды (`html/`)
- Оверрайд меню: `html/mod_menu/offcanvas.php` (раскрывающиеся пункты для мобильных).
- Оверрайд хрома секций: `html/layouts/chromes/section.php` (стиль модуля `section` с суффиксами `soft`, `gray`, `primary`, `dark`, `sm`, `lg`, `nopad`, `full`).
- Оверрайды RadicalMart: корзина и поиск используют родные события JavaScript. В `media/js/user.js` кнопка корзины слушает `onRadicalMartCartAfterUpdateDisplayData` и синхронизирует состояние `disabled`.

## 3. Регламент сборки и выпуска релизов

При внесении любых изменений соблюдайте следующий порядок:

1. **Контроль синтаксиса:**
   ```bash
   find . -name "*.php" -exec /Applications/ServBay/package/php/8.4/current/bin/php -l {} +
   ```
2. **Повышение версии (SemVer):**
   - Увеличить версию в `templateDetails.xml`: `<version>X.Y.Z</version>`.
   - Зафиксировать изменения в блоке `## Версия` в `README.md`.
3. **Сборка архива:**
   ```bash
   ./build.sh
   ```
   Скрипт создаст `dist/dharma_starter-X.Y.Z.zip` и выведет его SHA-256 хэш.
4. **Обновление ленты обновлений `updates.xml`:**
   - Добавить блок `<update>` на новую версию в начало файла `updates.xml` с указанием версии, ссылки на скачивание из GitHub Releases и вычисленного SHA-256.
5. **Коммит и отправка в репозиторий:**
   ```bash
   git add .
   git commit -m "Release vX.Y.Z: ..."
   git push origin main
   ```
6. **Публикация релиза на GitHub:**
   ```bash
   gh release create vX.Y.Z dist/dharma_starter-X.Y.Z.zip --title "vX.Y.Z — ..." --notes "..."
   ```
   В описании релиза обязательно указывать прямую ссылку на скачивание архива для установки по URL в Joomla.
